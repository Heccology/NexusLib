# Nexuslib version 1.2.0

## Fixes
- Fixed an issue where planks blocks weren't being added to the axe_mineable tag
- Fixed particles using the PARTICLE_SHEET_CLOUD particle render type rendering as black when any particle with the CUSTOM render type is being rendered as well (picking up items, Elder Guardian jumpscare, etc.) on neoforge
- Fixed NullPointerExceptions related to NexusLib services that occur intermittently

## Changes
- Added argument `ofThisMod` to `generateBlockFamilyModels` in `NLModelProvider`, `generateBlockFamilyBlockTags` in `NLBlockTagProvider`, and `generateBlockFamilyItemTags` in `NLItemTagProvider`
  - When true, only files of the matching mod id will be generated (default behavior in previous versions)
- Added argument `woodSuffix` to the method `logs` in `BlockFamilyCreator`
  - When false, the "_wood" suffix on wood log blocks will not be added (for when a wood type already has the word wood in it, for example Redwood)
  - Added map `LOG_TO_WOOD` which the method `logs` adds to
- Added toggleable model generation for logs
- Changed private fields in `BlockFamilyCreator` to be protected
- Tags for a block family block to be added to in `addExistingBlock` is now a function which passes in the block family to allow non static block lists to be accessed
- Reworked `addItemsToItemGroup` in `REGISTRY` service
  - Item origin and the stack to add are now handled through a `ItemGroupAddition` record
  - Position relative to the origin item can now be specified through the `ItemGroupAdditionType` value:
    - `ADD_AFTER` adds the item stack after the specified origin
    - `ADD_BEFORE` adds the item stack before the specified origin
    - `ADD_LAST` ignores the origin and force adds the item to the end of the item group

## New Features
- Added a contributor cape switcher settings option (thanks to Yirmiri)
  - Those who have contributor capes can now enable/disable/switch between available capes in a new menu item in "Skin Customization"
  - Added contributor capes "Subterrous" and "Subterrous Super"
- Added NLFluidInteractionRegistry
  - For defining interactions of a fluid when spreading, such as when cobblestone is made when water and lava meet
  - Supplies the fluid type, level, and block position, should return true (interaction was a success), or false
- Added NLDripstoneConversionRegistry
  - For adding custom dripstone block conversion interactions
  - Takes in the input block, the fluid type (what kind of particles the pointed dripstone should drip) and the resulting block state
- Added PaletteTemplateMatrix (`"nexuslib:palette_template_matrix"`) SpriteSource
  - Similarly to `paletted_permutations`, this applies a set of given color palettes to a set of given template textures
  - Instead of defining permutations in the sprite source definition, seperate json files within specified directories are used
  - Textures are saved to the location `assets/[template modid]/[template path]/[template texture name]_[palette modid]_[palette path]`
  - Can be defined as such:
    - `"id"` - the identifier for the specific use case
    - `"palette_key"` the template color palette sprite directory
    - `"palette_definition_directory"` the directory to search for palette definition files
    - `"template_definition_directory"` the directory to search for template definition files
  - Event listeners for additional functionality/reading additional json elements in definition files can be done through PTMEvents
    - `registerPaletteDiscoveryCondition` function that adds a condition to whether or not a certain palette should be discovered, provides the sprite source id, palette provider path, palette resource location, and the JsonObject
    - `registerTemplateDiscoveryCondition` function that adds a condition to whether or not a certain template should be discovered, provides the sprite source id, template provider path, template resource location, and the JsonObject
    - `registerOnPaletteDiscoveryEvent` runs when discovering palette definition files, provides the sprite source id, palette resource location, and the JsonObject
    - `registerOnTemplateDiscoveryEvent` runs when discovering template definition files, provides the sprite source id, template resource location, and the JsonObject
